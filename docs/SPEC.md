# אפיון: ניהול תקציב שיפוץ החנות

מסמך זה מסכם את האפיון שאושר. כל סכום באפליקציה הוא בשקלים.

## 1. מסכים

| מסך | תוכן |
|---|---|
| **לוח בקרה (ראשי)** | שישה כרטיסים: תקציב כולל, תחזית עלות, שולם, נותר לתשלום, רזרבה שנותרה, יתרה או חריגה צפויה (בש"ח ובאחוזים). גרף תקציב מול תחזית מול שולם. טבלת תחומים: סטטוס, התקדמות, תחזית, שולם, נותר. התראות ותשלומים קרובים. |
| **תחומי עבודה** | רשימת התחומים עם סטטוס ואחוז התקדמות; הוספה, עריכה ומחיקה. |
| **כרטיס תחום** | פרטי התחום וההתקדמות, השוואת הצעות מחיר ובחירת ההצעה הנבחרת, תוספות לחוזה, תשלומים (ששולמו ומתוכננים), הערות. |
| **הוצאות כלליות** | אגרות, ביטוחים, היתרים, יועצים וכדומה: הערכה, סכום בפועל ותשלומים. |
| **תשלומים** | כל התשלומים במקום אחד, עם סינון לפי סטטוס, תחום או ספק, ותצוגת התשלומים ב־30 הימים הקרובים. |
| **ספקים** | פרטי קשר, ובאילו תחומים כל ספק הגיש הצעה או נבחר. |
| **הגדרות** | שם הפרויקט, תקציב כולל, רזרבה, שיעור מע"מ, ובחירה אם התקציב והדוחות מוצגים לפני מע"מ או כולל מע"מ. |

## 2. מבנה נתונים

- **הגדרות פרויקט** (רשומה אחת): שם, תקציב כולל + סימון מע"מ, רזרבה, שיעור מע"מ (ברירת מחדל 18%), בסיס תצוגה (לפני מע"מ / כולל מע"מ).
- **תחום עבודה**: שם, סטטוס, אחוז התקדמות, הערכה ידנית + סימון מע"מ (לא חובה), ההצעה הנבחרת, הערות.
- **ספק**: שם, איש קשר, טלפון, מייל, ח.פ. או ע.מ., הערות.
- **הצעת מחיר**: תחום, ספק, סכום + סימון מע"מ, תאריך קבלה, בתוקף עד, תיאור, סטטוס (פתוחה / נדחתה). ההצעה הנבחרת נשמרת בתחום.
- **קובץ הצעה**: הצעת מחיר, שם הקובץ, סוג (PDF או תמונה), גודל, מי העלה ומתי, ומפתח האובייקט ב־R2. להצעה יכולים להיות כמה קבצים.
- **תוספת לחוזה**: תחום, תיאור, סכום (תוספת או זיכוי) + סימון מע"מ, תאריך, סטטוס (ממתינה / אושרה).
- **הוצאה כללית**: קטגוריה (אגרה, ביטוח, היתר, יועצים, אחר), תיאור, למי משלמים, הערכה + סימון מע"מ, סכום בפועל + סימון מע"מ, הערות.
- **תשלום**: שייך לתחום *או* להוצאה כללית. סכום + סימון מע"מ, תאריך, סטטוס (שולם / מתוכנן), אמצעי תשלום, מספר חשבונית או קבלה, הערות.

בכל רשומה נשמר מי יצר אותה, מי עדכן אותה ומתי.

**קשרים:** לתחום יש הרבה הצעות ולכל היותר הצעה נבחרת אחת. ספק יכול להופיע בכמה תחומים. אם בעבודה אחת יש כמה ספקים, מפצלים אותה לכמה תחומים.

**סטטוסי תחום:** טרם התחיל → איסוף הצעות → ספק נבחר → בביצוע → הושלם.

## 3. מע"מ

- בהגדרות הפרויקט בוחרים בסיס תצוגה: **לפני מע"מ** או **כולל מע"מ**. כל המסכים והדוחות מוצגים לפי הבחירה הזו.
- בכל סכום מסמנים אחת משלוש אפשרויות: **כולל מע"מ**, **לפני מע"מ** או **פטור ממע"מ**.
- לפני כל חישוב כל סכום מומר לבסיס התצוגה (r = שיעור המע"מ):

| הסכום סומן | תצוגה לפני מע"מ | תצוגה כולל מע"מ |
|---|---|---|
| כולל מע"מ | ÷ (1 + r) | כמו שהוא |
| לפני מע"מ | כמו שהוא | × (1 + r) |
| פטור | כמו שהוא | כמו שהוא |

התקציב הכולל והרזרבה מסומנים כולל או לפני מע"מ, ומומרים באותו אופן.

## 4. כללי חישוב

### לכל תחום
- **מחויב** = ההצעה הנבחרת + תוספות שאושרו. אם לא נבחרה הצעה: 0.
- **תחזית**:
  1. אם נבחרה הצעה: הסכום המחויב.
  2. אחרת, הערכה ידנית אם הוזנה.
  3. אחרת, ההצעה הפתוחה הזולה ביותר.
  4. אחרת, 0 והתחום מסומן "חסרה הערכה".
- **שולם** = סכום התשלומים בסטטוס "שולם".
- **נותר לתשלום** = max(תחזית − שולם, 0).
- תוספות שממתינות לאישור לא נכללות בתחזית ומוצגות בנפרד.

### לכל הוצאה כללית
- **תחזית** = הסכום בפועל אם הוזן, אחרת ההערכה, אחרת 0 ("חסרה הערכה").
- סכום בפועל נחשב מחויב; הערכה נחשבת עדיין לא סגורה.
- שולם ונותר — כמו בתחום.

### ברמת הפרויקט
- **תחזית עלות** = Σ תחזיות התחומים + Σ תחזיות ההוצאות הכלליות.
- **שולם** = Σ כל התשלומים ששולמו.
- **נותר לתשלום** = Σ הנותר של כל פריט בנפרד, כדי שתשלום יתר בפריט אחד לא יסתיר יתרה בפריט אחר. מפוצל ל"מחויב וטרם שולם" ול"טרם נסגר".
- **התקדמות כוללת** = ממוצע אחוזי ההתקדמות של התחומים, משוקלל לפי התחזית.

### רזרבה
הרזרבה היא חלק מהתקציב הכולל ויורדת אוטומטית כשהעלויות מגיעות אליה:
- **תקציב לעבודות** = תקציב כולל − רזרבה.
- **ניצול רזרבה** = min(max(תחזית − תקציב לעבודות, 0), רזרבה).
- **רזרבה שנותרה** = רזרבה − ניצול.
- **יתרה / חריגה צפויה** = תקציב כולל − תחזית עלות. חיובי: צפוי להישאר. שלילי: חריגה.

דוגמה: תקציב 500,000 ₪, רזרבה 50,000 ₪. תחזית 470,000 ₪ → נוצלו 20,000 ₪, נותרו 30,000 ₪, אין חריגה. תחזית 520,000 ₪ → הרזרבה נוצלה כולה, חריגה 20,000 ₪.

### התראות
- התחילו לנצל את הרזרבה; נוצלה חצי ממנה; נוצלה כולה / חריגה מהתקציב.
- בתחום או בהוצאה שולם יותר מהתחזית.
- בתחום אחוז התשלום גבוה מאחוז ההתקדמות ביותר מ־10 נקודות.
- תחום או הוצאה שחסרה להם הערכה.
- הצעה פתוחה בתחום שעוד לא נבחרה בו הצעה, שתוקפה פג או יפוג תוך 14 יום.
- תשלום מתוכנן שמועדו עבר.
- תוספות לחוזה שממתינות לאישור.

## 5. משתמשים, הרשאות וקבצים
- כמה משתמשים, כל אחד מהטלפון שלו.
- הכניסה דרך Cloudflare Access: קוד חד־פעמי למייל, ורק מיילים שברשימה יכולים להיכנס. ההתחברות נשמרת שבוע, גם בטלפון.
- כל בקשה ל־API צריכה זהות ש־Access אימת. המקור הראשי הוא `ctx.access`, וה־`aud` שלו חייב להתאים לאפליקציה. אם `ctx.access` חסר, ה־Worker מאמת בעצמו את ה־JWT של Access. כתובת מייל בכותרת רגילה לא מתקבלת, ובקשה בלי זהות מאומתת נחסמת.
- לכל המשתמשים אותן הרשאות.
- קובצי הצעות (PDF, JPEG, PNG, WebP, HEIC, עד 15MB) נשמרים ב־R2 פרטי ונגישים רק דרך ה־API, למשתמשים מחוברים. הסוג נקבע לפי תוכן הקובץ. מחיקת קובץ, הצעה או תחום מוחקת גם את הקבצים.

## 6. טכנולוגיה
- אפליקציית אינטרנט בעברית, מותאמת לטלפון, שאפשר להתקין כאייקון במסך הבית באייפון ובאנדרואיד. היא נפתחת במסך מלא, ויש בה מסך עם הוראות התקנה.
- Cloudflare Workers (אתר + API), D1 (מסד נתונים), R2 (קבצים), Access (התחברות).
- כתובת התחלתית: `workers.dev`, מוגנת ב־Access. דומיין משלכם אפשר להוסיף בהמשך.
